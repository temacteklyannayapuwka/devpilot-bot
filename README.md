# DevPilot Bot

Личный Telegram-пульт для разработки через Codex CLI на Mac: задачи в нескольких проектах, расписание, выбор модели, тесты, коммиты и отчёты. Работает через long polling без публичного входящего порта. Команды доступны только владельцу в личном чате.

## Возможности

- Постоянная панель лимитов Codex: процент остатка и время сброса, обновление одного сообщения каждые 5 минут.
- Список доступных моделей из Codex и сохранение выбора для новых запусков.
- Очередь конкретных задач, ручной запуск, отмена, повтор и история.
- Отдельное рабочее дерево Git и ветка `devpilot/task-ID` для каждой задачи.
- Обязательные команды проверок из конфигурации перед коммитом.
- Режим `review`: коммит сохраняется локально и ждёт `/publish ID`.
- Режим `auto`: после проверок коммит отправляется в `origin/<branch>` проекта.
- Интервальное расписание, пауза, сохранение очереди и уведомлений в SQLite.
- Автозапуск после входа в macOS через LaunchAgent.

За один запуск выполняется одна поставленная задача. Без задач в очереди расписание не создаёт работу самостоятельно. Одновременно выполняется одна задача. Результат в `review` блокирует следующие задачи того же проекта до публикации или отклонения. Другие проекты могут продолжать работу.

Git push выполняется без force. При конфликте удалённой ветки публикация останавливается, коммит остаётся для ручной проверки. Основной локальный checkout не переключается и не обновляется; незакоммиченные изменения в нём блокируют новую задачу. После публикации новые задачи берут свежую базу из `origin`, даже если основной локальный checkout отстаёт.

## Переписка с существующим диалогом Codex

Для работы в текущем проекте и с сохранённым контекстом используй режим диалога:

1. `/projects` — посмотреть подключённые проекты. В меню Telegram также есть кнопки `/use ИМЯ`.
2. `/sessions hookrelay` — посмотреть доступные через Codex CLI диалоги каталога проекта.
3. `/bind hookrelay ID` — привязать нужный существующий диалог. Его каталог должен совпадать с каталогом проекта, а текущий ответ Codex должен быть завершён. Если диалог не попал в список, можно указать известный ID локальной сессии напрямую.
4. Пиши обычные сообщения: например, «Продолжай по нашему плану, следующий коммит». Бот отправит их в привязанный диалог и вернёт ответы Codex в Telegram с подписью проекта.

`/use microwatch` переключает активный проект, `/project` показывает его состояние Git и привязанный диалог, `/leave` отключает отправку обычных сообщений. Привязки и активный проект сохраняются после перезапуска. Переключение не меняет проект уже поставленных сообщений. Ответы других подключённых проектов продолжают приходить с соответствующей подписью.

В режиме переписки бот вызывает `thread/resume` и `turn/start` для одного и того же ID. Новый диалог или копия проекта автоматически не создаются. Изменения происходят непосредственно в настроенном локальном каталоге; коммиты и push в этом режиме выполняет Codex по твоим сообщениям и разрешениям, а не исполнитель `/task`. Не запускай параллельную работу в том же диалоге с компьютера. `/cancel ID` прерывает отправленный ботом ход; изменения не откатываются.

После привязки бот также проверяет последние завершённые ответы диалога каждые 30 секунд. Это позволяет получать в Telegram ответы на ходы, начатые на Mac. Старые ответы на момент привязки пропускаются, повторные уведомления фильтруются. Во время отключения бота длинная история не выгружается: при восстановлении проверяются последние 10 ходов. Время проверки может увеличиться при нескольких проектах и сетевых ошибках. Наблюдение читает историю, доступную локальному Codex App Server; оно не перехватывает окна приложения и не управляет ими.

Обычный вопрос Codex появляется сообщением в Telegram, ответь обычным текстом. Если Codex использовал интерактивную форму с одним вопросом, обычный текст также отправится как ответ. Для нескольких вопросов бот покажет команды `/answer ТОКЕН ID_ВОПРОСА текст`. Запросы разрешения на команды и изменение файлов требуют явного `/approve ТОКЕН` или `/deny ТОКЕН`; бот сам их не одобряет. Неподдерживаемые интерактивные запросы завершаются сообщением об ограничении. Ожидание ответа входит в `timeout_seconds` проекта.

Режим доступен только для сессий, которые действительно доступны локальному Codex CLI на Mac. Чаты ChatGPT Work и облачные задачи не становятся локальными сессиями автоматически. Если нужной переписки там нет, бот её не сможет продолжить по одному названию проекта. Привязка проверяется при настройке и перед отправкой хода.

Отдельный режим `/task` сохраняет прежнее поведение: конечная задача, изолированное рабочее дерево, проверки и публикация с `/publish` или автоматически. `/pause` приостанавливает новые ходы из Telegram и задачи, но наблюдение и доставка ответов продолжаются. `/stop` отключает только панель лимитов.

## Требования

- macOS, Python 3.11+, Git и Codex CLI в PATH или по абсолютному пути `CODEX_BIN`.
- Авторизация Codex через `codex login` и Git-доступ на чтение/запись к `origin` каждого проекта.
- Настроенные `git user.name` и `git user.email`.
- Компиляторы, зависимости и команды тестирования соответствующих проектов.
- Telegram-бот от `@BotFather`, его токен и числовой ID владельца.

Сторонние Python-пакеты не требуются. Токен бота не передаётся дочерним процессам. Файлы с распространёнными именами секретов блокируются перед коммитом; это дополнительная проверка имён, а не полноценный сканер секретов.

## Запуск на Mac

```bash
git clone https://github.com/temacteklyannayapuwka/devpilot-bot.git
cd devpilot-bot
cp .env.example .env
chmod 600 .env
```

В `.env` заполни `TELEGRAM_BOT_TOKEN` и `TELEGRAM_OWNER_ID`. Если `codex` не найден в PATH, укажи его абсолютный путь в `CODEX_BIN`. `LIMITS_INTERVAL_SECONDS` задаёт интервал панели, минимум 60 секунд. `TIMEZONE` задаёт часовой пояс отображения времени, по умолчанию `Europe/Moscow`.

Бот читает `.env` сам, без выполнения shell-команд. Уже заданные переменные окружения имеют приоритет. Не публикуй `.env`, токены и локальное состояние.

Создай `projects.json`. Пример для одного проекта:

```json
{
  "microwatch": {
    "path": "~/Projects/microwatch",
    "branch": "main",
    "checks": [["go", "test", "./..."], ["go", "vet", "./..."]],
    "timeout_seconds": 1800
  }
}
```

`branch` — удалённая ветка, от которой создаётся рабочее дерево и в которую отправляется коммит при публикации. Для проектов с другой основной веткой укажи её имя. `checks` — непустой список команд, каждая задаётся массивом аргументов и выполняется без shell в рабочем дереве. При необходимости используй абсолютные пути к интерпретаторам. `timeout_seconds` ограничивает каждую длительную команду, допустимо 60–14400 секунд.

В `projects.example.json` есть примеры Go, Maven и Python. Скопируй только нужные записи, замени пути и команды проверок на действительные для своих репозиториев. Бот не устанавливает зависимости проектов автоматически.

```bash
codex login
python3 doctor.py
python3 bot.py
```

Открой личный чат с ботом и отправь `/start`. Появятся меню команд и обновляемая панель лимитов. Используй токен без настроенного webhook. Запускай один экземпляр приложения. Для обновления конфигурации проектов перезапусти бота.

## Команды Telegram

| Команда | Действие |
|---|---|
| `/projects` | Подключённые проекты, пути и целевые ветки |
| `/task microwatch Добавить проверку таймаута` | Добавить конкретную задачу в очередь |
| `/run microwatch` | Подготовить следующую задачу проекта к запуску |
| `/tasks [проект]` | Последние 20 задач |
| `/commits [проект]` | Задачи с коммитами среди последних 20 |
| `/job 1` | Отчёт, SHA, ссылка на GitHub и путь журнала |
| `/cancel 1` | Отменить ожидающую или выполняемую задачу разработки |
| `/retry 1` | Создать повтор неуспешной или отклонённой задачи |
| `/publish 1` | Отправить проверенный коммит в целевую ветку |
| `/reject 1` | Отклонить локальный результат, сохранив рабочее дерево |
| `/mode review` | Ждать подтверждения публикации; режим по умолчанию |
| `/mode auto` | Публиковать новые результаты после проверок |
| `/schedule microwatch 6` | Брать одну задачу проекта каждые 6 часов |
| `/schedule microwatch off` | Отключить расписание проекта |
| `/schedule` | Интервалы и время следующих попыток запуска |
| `/pause` / `/resume` | Приостановить / разрешить новые запуски |
| `/models` | Доступные модели Codex |
| `/model ИМЯ` | Выбрать модель для новых запусков |
| `/model` / `/model default` | Показать выбор / вернуть выбор Codex по умолчанию |
| `/limits` | Новая панель лимитов |
| `/stop` | Остановить только обновление панели лимитов |
| `/status` / `/help` | Состояние / справка |

Пример: поставь задачу через `/task`, запусти `/run`, дождись отчёта и отправь `/publish ID`. Для автоматической работы включи `/mode auto`, заполни очередь и настрой `/schedule`.

Интервал расписания — 1–168 часов, дробные значения допустимы. Первая попытка запуска будет через заданный интервал. После сна или паузы пропущенные интервалы не воспроизводятся пачкой: выполняется одна попытка, затем отсчитывается новый интервал. Пауза не прерывает активную задачу и не отменяет её публикацию. `/stop` не останавливает разработку. Новая модель и режим публикации не меняют уже выполняемую команду Codex; режим публикации проверяется при завершении задачи.

## Автозапуск macOS

Сначала проверь обычный запуск и останови его через Ctrl+C.

```bash
python3 service.py install
python3 service.py status
```

Сервис запускается после входа пользователя в macOS и перезапускается при завершении процесса. Используется `caffeinate -i`, чтобы предотвращать обычный сон от бездействия во время работы сервиса. Выключение Mac и сон при закрытии крышки прерывают доступность. Это пользовательский сервис, а не запуск до входа в систему.

```bash
python3 service.py uninstall
```

После обновления кода выполни установку сервиса повторно для перезапуска. При установке сохраняется текущий PATH; выполняй её из терминала, где доступны инструменты проектов.

## Хранение и восстановление

Локальные файлы находятся в `.devpilot/` и исключены из Git:

- `state.sqlite3` — задачи, расписание, пауза и исходящие уведомления.
- `settings.json` — выбранная модель.
- `runs/ID/worktree` — файлы задачи; `runs/ID/run.log` — вывод Codex и проверок.
- `service.log`, `service-error.log` — журналы автозапуска.

После обычной ошибки разработки новые запуски ставятся на паузу. Посмотри `/job ID`, исправь окружение, при необходимости создай `/retry ID`, затем `/resume` и `/run ПРОЕКТ`. Отказ публикации оставляет готовый коммит в `review`. Git-конфликты решаются вручную, история автоматически не переписывается.

После аварийного завершения активные задачи получают статус `interrupted`, новые запуски ставятся на паузу. Перед повтором проверь журнал, процессы, рабочее дерево и удалённую ветку: публикация могла завершиться непосредственно перед сбоем. Прерванные задачи автоматически не повторяются.

Рабочие деревья и журналы сохраняются для проверки и не удаляются автоматически. После проверки закрытой задачи удали её рабочее дерево стандартной командой `git worktree remove ПУТЬ`, затем при необходимости удали локальную ветку и журнал. Не удаляй деревья активных задач.

Исходящие отчёты сохраняются при недоступности Telegram и повторяются после восстановления соединения. При сбое между доставкой и подтверждением возможен повтор сообщения. ID входящих обновлений сохраняются для защиты от повторного выполнения команды; после аварии сверь состояние через `/tasks`.

## Лимиты и выполнение Codex

Панель читает `account/rateLimits/read`, выбор моделей — `model/list` через локальный Codex App Server. Лимиты показываются только когда сервис их предоставил: процент остатка и время сброса, без выдуманного числа сообщений. Отсутствующие данные отображаются как недоступные. При сетевой ошибке обновление может задержаться; время последней успешной проверки видно в панели. Это показатели Codex, а не всех функций ChatGPT.

Разработка запускается через `codex exec --sandbox workspace-write` без интерактивного одобрения команд. Если операция требует дополнительных разрешений, задача может завершиться ошибкой. Разрешения не расширяются автоматически. Используется текущая авторизация CLI; доступность модели и лимиты определяются аккаунтом.

## Проверка

```bash
python3 -m unittest discover -s tests -v
```

Тесты проверяют очередь, расписание, доступ, модели, протокол App Server, таймауты и Git-публикацию на временных локальных репозиториях. Генерация кода заменена тестовым исполнителем; эти тесты не расходуют лимиты аккаунта. Подключение к реальному Telegram, Codex и LaunchAgent проверяется отдельно на Mac.
